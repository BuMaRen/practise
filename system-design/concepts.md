# 常用系统设计概念

整理自原仓库系统设计知识点清单。共 28 个概念，按主题和熟练优先级排列。每项给出学习范围，具体设计时应根据需求判断是否适用。

优先级：**核心**（常见设计问题的基础）、**常见**（经常遇到）、**进阶**（需深入理解）。建议先学核心概念，再按每日题目暴露出的缺口补充。

## 估算与接口

### 核心
- **容量估算**：日活到请求量的换算、峰值系数、读写比例、数据大小与保留量、带宽估算；用估算结果解释容量边界。

### 常见
- **延迟与性能指标**：吞吐与延迟、P50/P95/P99、内存/磁盘/网络耗时量级、Little 定律及其适用条件。
- **API 设计**：资源建模、REST 与 RPC 取舍、分页、错误语义、幂等、版本演进和兼容性。
- **分布式唯一 ID**：自增 ID、UUID、雪花类 ID、号段；关注唯一性、趋势性、时钟回拨和索引局部性。

## 扩展与负载

### 核心
- **水平扩展与无状态服务**：垂直/水平扩展、会话状态外置、有状态服务扩展、自动扩缩容信号。
- **负载均衡**：L4/L7、轮询/加权/最少连接/哈希、健康检查、摘除、会话保持及客户端/服务端负载均衡。
- **分库分表与分片**：垂直/水平拆分、分片键、范围/哈希策略、热点、跨分片查询与事务、扩容迁移。
- **复制与读写分离**：主从/多主、同步/异步复制、复制延迟、故障切换、冲突和数据丢失窗口。

### 常见
- **一致性哈希**：取模扩容迁移问题、哈希环、虚拟节点、负载均衡和数据迁移边界。

## 缓存

### 核心
- **缓存模式与失效**：Cache-Aside、读穿/写穿/写回、更新与删除顺序、TTL、淘汰策略、缓存与源数据一致性。
- **缓存穿透、击穿与雪崩**：三类问题的成因与影响；空值缓存/布隆过滤器、热点重建控制、过期抖动、多级缓存与降级的适用条件。

### 常见
- **CDN 与边缘缓存**：回源、缓存键、刷新/失效、静态资源版本、动态内容加速和成本。

## 数据与一致性

### 核心
- **一致性模型**：线性一致、顺序一致、最终一致、读己之写、单调读；从业务要求选择可见性承诺。
- **事务与隔离级别**：ACID、脏读/不可重复读/幻读、隔离级别、MVCC、悲观/乐观并发控制和丢失更新。
- **分布式事务**：2PC、TCC、Saga、本地消息表/Outbox；协调阻塞、补偿语义、部分成功与适用边界。

### 常见
- **CAP 与 PACELC**：网络分区时一致性与可用性的含义，以及无分区时延迟和一致性的取舍。
- **存储选型**：关系型、KV、文档、列式、搜索及时序存储；按访问模式、事务、索引、扩展和运维能力选择。

### 进阶
- **索引与存储引擎**：B+ 树与 LSM 的读写特性、范围查询、读写放大、合并和布隆过滤器。

## 异步与消息

### 核心
- **消息队列与交付语义**：削峰/解耦/异步、至多一次/至少一次及“恰好一次”的边界、确认时机、顺序、积压、死信与重放。
- **幂等设计**：幂等键、请求 ID、唯一约束、状态机约束、去重有效期及外部副作用。
- **超时、重试与退避**：可重试错误、超时预算、指数退避与抖动、重试预算、重试放大和级联故障。

### 进阶
- **事件驱动与 CQRS**：事件通知与事件携带状态、事件溯源、读写模型分离、最终一致性代价和事件版本演进。

## 可靠性与稳定性

### 核心
- **限流**：令牌桶、漏桶、固定/滑动窗口；突发处理、限流维度、单机/分布式策略和拒绝语义。
- **熔断、降级与隔离**：熔断状态、降级条件、线程/连接池隔离、背压以及依赖恢复后的放量。

### 常见
- **分布式锁**：原子获取、过期与续期、误删、fencing token；评估是否可用数据约束或单写者模型简化。

### 进阶
- **共识、选主与租约**：多数派、Raft 选主和日志复制、脑裂、租约时钟假设及一致性服务的边界。

## 安全与运维

### 常见
- **可观测性与 SLO**：RED/USE 指标、结构化日志、Trace/Span、SLI/SLO/错误预算、有效告警和排障路径。
- **认证与授权**：Session/Token、JWT 吊销、OAuth2 授权码、RBAC/ABAC、多租户隔离和密钥管理。

## 概念学习方法

学习一个概念时，能说明它解决的问题、基本工作方式、适用与不适用条件、成本和失败边界；再用一个不同业务场景检验迁移能力。设计题中只在需求支持时使用某种机制，并解释替代方案与取舍。概念名称本身不构成设计论证。

## 概念详解

本节逐项展开上面的 28 个概念。每节覆盖核心机制、适用判断、主要代价和易错点；它们用于建立理解，不是设计题的预设答案。

### 1. 容量估算

容量估算是在设计前用业务量级判断系统需要处理多少请求、数据和流量。先把用户行为换算成操作量：日请求量除以 86,400 得到平均 QPS，再乘峰值系数得到峰值；不要把日活直接当 QPS。读写比例、批量大小、重试流量和促销峰值也要算入。

存储估算用每日新增条数乘平均记录大小和保留天数，再分别加上索引、副本、日志及增长余量。带宽用每秒请求数乘平均响应字节数估算。并发量可用 Little 定律近似为吞吐乘平均处理时长。估算值应注明假设和单位，并做低/中/高情景；若结果改变存储、缓存、分片或成本选择，才进一步细化。常见错误是只算平均值、遗漏峰值和重试，或把估算精度伪装成精确预测。

### 2. 延迟与性能指标

吞吐表示单位时间完成的工作量，延迟表示单个操作花费的时间；负载接近容量上限时，排队会让延迟迅速上升。平均延迟会掩盖少数慢请求，P95/P99 表示相应比例请求的延迟不超过该值，适合观察尾延迟。端到端延迟由排队、网络、服务处理和依赖调用共同组成。

Little 定律 L=λW 表示稳定系统中平均在途工作量等于到达率乘平均逗留时间。它不直接说明系统能否承受突发或不稳定负载。性能目标要落到具体操作和测量窗口，并记录成功率、吞吐和分位延迟。常见误区是单看平均值、把微基准当生产表现，或忽略排队和下游依赖。

### 3. API 设计

API 是调用方与服务之间的长期契约。先围绕业务资源与动作设计输入输出，再明确认证授权、分页、排序、错误码、超时、重试和版本兼容。REST 常以资源和标准 HTTP 语义组织接口；RPC 常适合服务间明确方法调用、强类型契约或流式通信。实际选择还要考虑团队工具、网络边界和客户端生态。

分页避免一次返回无限数据；偏移分页便于跳页，但大偏移可能昂贵且并发变更时结果漂移；游标分页适合稳定遍历，但依赖排序键和游标有效性。写接口要说明重复提交的语义、冲突如何表达、调用方如何安全重试。版本演进优先保持向后兼容，新增字段需允许旧客户端忽略。常见错误是只定义成功响应，未定义超时后结果未知时如何查询或重试。

### 4. 分布式唯一 ID

唯一 ID 在多个节点并行创建实体时避免集中取号或碰撞。自增 ID 简单且局部有序，但集中数据库可能成为瓶颈并暴露业务规模；随机 UUID 可独立生成且碰撞概率极低，但体积大、索引写入局部性差；时间加节点标识的 ID 可近似有序，但依赖节点标识唯一、时钟稳定和位段规划；号段由中心批量分配，减少每次取号开销，但需管理段耗尽和故障。

选择时明确唯一性范围（全局、租户或表内）、排序需求、可猜测性、索引影响和离线生成要求。雪花类算法遇到时钟回拨不能盲目继续发号；节点 ID 配置冲突会制造重复。不要把 ID 当作授权凭证，也不要依赖 ID 的不可预测性保护资源。

### 5. 水平扩展与无状态服务

垂直扩展是给单机增加 CPU、内存或磁盘，操作较简单但存在硬件上限和单点；水平扩展是增加节点，提升容量和故障承受能力，但需要负载分配、状态共享和部分失败处理。无状态服务节点不保存请求间唯一的重要状态，任一健康节点可处理后续请求，因此更容易扩缩容和替换。

会话、任务进度等状态可以放在共享存储或专门的状态服务中，但这会把压力转移到状态层。自动扩缩容应观察队列等待、CPU、并发、延迟等能反映需求的信号，并考虑启动时间和冷却时间。只按 CPU 扩容可能错过 I/O 或队列瓶颈；快速缩容也可能中断长请求或任务。有状态服务并非不能扩展，但需明确分区、迁移、复制和节点故障时的状态归属。

### 6. 负载均衡

负载均衡把请求分配到多个实例。L4 主要依据连接和网络信息转发，开销较小；L7 能依据 HTTP 等应用信息路由，策略更丰富但需要理解协议。轮询实现简单；加权轮询适配不同容量；最少连接适合处理时间差异较大的长连接；哈希路由可维持数据或会话亲和性，但可能造成热点。

健康检查应判断实例是否能提供目标服务，避免只检查进程存活。故障实例摘除、连接排空和恢复放量需协调。会话保持降低状态迁移要求，却削弱均衡并使实例退出影响会话；优先评估将会话状态外置。负载均衡器本身也需高可用，客户端负载均衡要解决服务发现和策略更新。

### 7. 分库分表与分片

分片把数据或请求分散到多个节点，常用于单节点容量或吞吐已成为可测瓶颈的场景。垂直拆分按业务/字段分开，水平拆分按记录分区。分片键决定数据位置和查询路由：哈希分布通常均匀但范围查询困难；范围分布支持范围扫描但写入可能集中在边界。

设计要检查主查询是否包含分片键、热点租户或时间段、跨分片事务和聚合、全局唯一 ID、索引、备份恢复以及迁移扩容。扩容不是简单加机器：数据需重分布并保持读写一致。过早分片会显著增加运维和查询复杂度；通常先以真实容量证据和明确迁移路径证明需要分片。

### 8. 复制与读写分离

复制把数据从主节点传播到副本，以提高读容量、容灾或跨区域读取。同步复制在确认写入前等待副本确认，通常降低数据丢失窗口但增加延迟并可能降低可写性；异步复制更快，但故障时可能丢失尚未复制的数据。读写分离把部分读请求发往副本，却会受复制延迟影响，出现写后读不到刚写数据。

对关键读可回主节点、等待副本追平或携带版本/会话信息；这些措施有不同延迟与复杂度。主从切换需确保旧主不会继续写入，避免脑裂；多主复制要定义冲突解决。副本不是备份，误删和逻辑错误也会被复制，需另有备份与恢复演练。

### 9. 一致性哈希

一致性哈希将节点和键映射到一个环上，键由环上顺时针遇到的节点负责。增加或删除节点时，理论上只需迁移相邻区间的数据，而不是像简单取模那样大范围重映射。虚拟节点让每个物理节点在环上有多个位置，改善负载均衡。

它适合缓存或分布式路由中希望降低拓扑变化迁移量的场景，不会自动解决数据复制、持久化、一致性或热点问题。节点权重、虚拟节点数量和数据迁移流程需另行设计。热点键仍会压垮单个节点；环拓扑变化期间还需定义缓存失效或数据读取行为。

### 10. 缓存模式与失效

缓存用较快介质保存可重建或可容忍一定陈旧的数据。Cache-Aside 常见流程是应用先读缓存，未命中再读源数据并写缓存；更新时通常先提交源数据，再删除缓存。读穿/写穿由缓存层协助访问源，写回先改缓存并异步落盘，写回提高写性能但增加数据丢失风险。

TTL 限制陈旧数据时间，淘汰策略在内存不足时决定移除项。缓存和数据库通常无法原子更新，短暂不一致不可避免；应根据业务定义可接受陈旧窗口和修复方式。先更新缓存再更新数据库可能将未提交值暴露；只删除缓存也会遇到并发读重建旧值。缓存命中率不是唯一目标，还应观察回源延迟、失效风暴和数据正确性。

### 11. 缓存穿透、击穿与雪崩

穿透是大量查询不存在的键，导致每次都回源；可对短期不存在结果缓存、校验请求或使用布隆过滤器拦截大部分不存在键。布隆过滤器可能误判存在，但不会误判不存在（标准结构下），且需考虑更新与重建。击穿是单个热点键过期后大量请求同时回源；可用请求合并、互斥重建或逻辑过期控制并发。

雪崩是大量键同时失效或缓存整体不可用导致后端流量骤增；可错开 TTL、分层缓存、限流、降级并保护源站。空值缓存可能掩盖刚创建的数据，TTL 不应过长。缓存失效保护不是单一技术，关键是约束回源压力并定义无法提供新鲜数据时的行为。

### 12. CDN 与边缘缓存

CDN 将内容缓存在靠近用户的边缘节点，减少跨地域往返并降低源站流量。缓存命中取决于缓存键，通常包含 URL、必要查询参数和相关请求头；键设计不当可能混淆不同用户内容或降低命中率。静态文件可通过内容哈希版本化，避免依赖大范围刷新；动态内容则需谨慎设置可缓存条件。

缓存过期后边缘节点可能回源，突发失效会造成源站压力。刷新/失效存在传播延迟，需定义用户能接受的陈旧程度。涉及个性化、权限或敏感信息的响应不能误共享缓存。评估 CDN 时同时考虑命中率、回源、区域覆盖、失效能力和成本。

### 13. 一致性模型

一致性描述并发操作和副本下，用户能观察到什么顺序与新鲜度。线性一致要求操作看起来在调用与返回之间某个瞬间原子发生，并遵循真实时间先后；顺序一致要求所有人看到同一操作顺序，但不一定符合真实时间。最终一致表示停止写入且传播成功后副本最终收敛，不保证何时收敛。

读己之写保证用户读到自己先前写入；单调读保证同一用户不会回退到更旧状态。这些会话保证常能以较低成本改善体验。选择模型应从业务后果出发：余额、库存等和展示类数据的容忍度不同。强一致通常增加协调、延迟或不可用窗口；最终一致则需处理重复、冲突和短暂旧读。不要笼统声称系统“强一致”，要说明对象、操作和范围。

### 14. 事务与隔离级别

事务把一组数据操作作为原子单位，并以 ACID 描述原子性、一致性、隔离性和持久性。隔离级别限制并发事务互相观察的中间状态。读未提交可读到未提交数据；读已提交避免脏读；可重复读保证同一事务重复读取行值稳定；可串行化要求结果等价于某种串行执行，通常并发代价最高。具体数据库的实现和异常边界可能不同。

MVCC 用多个版本减少读写互相阻塞；乐观并发控制先计算再以版本条件提交，适合冲突较少；悲观锁先锁定资源，适合冲突高且临界区短的情况。隔离级别不替代业务不变量设计。跨服务事务无法靠单个数据库事务保证，长事务还会占用锁和版本空间。

### 15. 分布式事务

分布式事务涉及多个独立资源或服务的协同。2PC 由协调者先准备、再提交，能提供原子提交语义，但协调者或参与者故障可能阻塞，且要求参与方支持协议。TCC 将业务拆成 Try、Confirm、Cancel，资源需预留并实现可重试确认/取消；语义清晰但侵入业务。

Saga 将长流程拆为本地事务序列，失败时按已完成步骤执行补偿。补偿是新的业务操作，未必能抹去外部可见事实。Outbox 在本地事务中同时写业务变更和待发事件，再异步投递，解决数据库提交与消息发送双写窗口；消费者仍需幂等。选择取决于一致性要求、参与方能力、流程长度和补偿可行性，不要默认追求全局强事务。

### 16. CAP 与 PACELC

CAP 讨论网络分区发生时，分布式系统不能同时保证线性一致性和对所有请求都成功响应。分区是通信故障，不是任意两项中静态挑选；系统需决定无法联系部分节点时是否拒绝/等待，还是继续接受可能冲突的请求。CAP 中可用性是严格定义的请求响应保证，不等于“服务大部分时间在线”。

PACELC 补充：即使没有分区（Else），系统也常在延迟与一致性之间取舍。实际设计要描述分区时不同操作的行为、正常情况下跨节点协调成本和业务容忍度。不要简单给数据库贴“CP/AP”标签后就结束分析。

### 17. 存储选型

存储选型从访问模式与数据约束出发。关系数据库适合结构化关系、事务和灵活查询；KV 适合按键快速读写；文档存储适合聚合对象结构变化；列式/分析型存储适合大规模扫描聚合；搜索引擎提供全文与相关性检索；时序存储优化时间戳序列和保留策略。

选型还需考虑写入/查询比、索引、事务范围、一致性、数据规模、备份恢复、扩展、团队经验和总成本。搜索索引通常是派生数据，不应默认成为业务权威源；多存储意味着同步延迟、重建和双份运维。先明确关键查询和不变量，再比较候选存储的证据，不按流行度选型。

### 18. 索引与存储引擎

B+ 树通过有序多层索引支持点查和范围扫描，叶子节点通常按序连接；更新可能涉及随机写和节点分裂。LSM 系列先将写入追加到内存结构和日志，再批量写入有序文件并后台合并，适合高写入场景，但读取可能检查多个层级，合并造成写放大和资源竞争。

布隆过滤器用于快速判断某层可能没有某键，降低无效磁盘读取，存在假阳性。索引会增加写放大、存储和维护成本；每个索引应有查询收益证据。选择引擎关注读写比例、范围查询、延迟分布、数据规模和后台合并对尾延迟的影响，不只看峰值吞吐。

### 19. 消息队列与交付语义

消息队列让生产者和消费者在时间与处理速率上解耦，可吸收短时突发，但不会消除长期处理能力不足。至多一次可能丢消息但不重复；至少一次减少丢失但可能重复；所谓恰好一次通常只在特定队列/事务边界内成立，跨数据库或外部副作用仍需幂等。

确认消息的时机决定故障时重放或丢失风险。分区通常提供分区内顺序而非全局顺序。需要监控积压量和最老消息年龄，设置消费容量、背压、重试上限、死信与安全重放流程。消息模式需版本化；长期积压会让旧事件和新消费者兼容问题显现。

### 20. 幂等设计

幂等表示同一操作重复执行多次，最终业务效果与执行一次相同。常用于客户端超时重试、队列重复投递和外部回调。幂等键需由调用方或系统生成，定义作用域、有效期及与请求内容的绑定；相同键但不同参数应明确拒绝或视为冲突。

实现可依赖唯一约束、条件状态更新、请求结果记录或外部系统提供的幂等接口。单纯先查后写在并发下会竞争，需原子约束。去重记录保留太短会让迟到重试再次生效，保留太久则增加存储。对不可幂等的外部副作用，要有对账、补偿或人工处置路径。

### 21. 超时、重试与退避

超时限制调用方等待时间，但不证明服务端没有完成操作；超时后结果可能未知。超时应由端到端预算分配到各依赖，避免每层都重置完整等待时间。重试只适用于暂时性错误且操作可安全重复的情况；参数错误、权限失败通常不应重试。

指数退避逐步拉长等待，加入随机抖动可避免大量客户端同步重试。设置最大次数、总时间和重试预算，避免重试放大故障。多层重试会乘法增加负载。异步操作可返回操作标识供后续查询。必须区分连接超时、请求超时和处理超时，并让取消真正传递到下游（若可行）。

### 22. 事件驱动与 CQRS

事件驱动通过发布状态变化让多个消费者异步响应，减少直接依赖；事件应说明事实而非要求某个消费者执行内部步骤。事件通知可只传标识，消费者再读取当前状态；事件携带状态便于独立处理，但需解决版本和数据体积。事件溯源将事件序列作为权威记录，可重建状态和审计历史，但查询通常需要投影。

CQRS 将写入模型和读取模型分开优化，读取投影通常异步更新，因此会有可见延迟和重建成本。Outbox 等方式可保证业务提交与事件待发记录原子。消费者应处理重复、乱序和旧版本事件。引入这些模式会增加调试、运维与数据一致性复杂度，只有读写负载或业务边界确实需要时采用。

### 23. 限流

限流控制一定时间内允许的请求量，保护自身和下游。固定窗口简单但窗口边界可能出现双倍突发；滑动窗口更平滑但状态更多；令牌桶允许一定突发后按速率补充令牌；漏桶以较稳定速率排出请求，平滑流量但会增加等待或拒绝。

限流维度可以是全局、租户、用户、接口或资源，需避免单一大客户挤占所有容量。分布式限流更一致但引入协调成本和限流器依赖；本地限流可用性较好但总额度只是近似。被限请求应有明确重试提示/错误语义，并设置公平性、突发额度和豁免规则。限流器故障时的默认行为需按保护目标决定。

### 24. 熔断、降级与隔离

熔断器根据失败率或慢调用情况暂时停止向故障依赖发送请求，通常经历关闭、打开、半开状态；半开允许少量探测恢复。熔断降低无效等待和故障传播，但阈值和探测策略不当会误判或抖动。降级是依赖不可用时提供较低质量但仍有价值的行为，例如隐藏非核心能力；需明确陈旧数据和功能缺失的边界。

隔离通过独立线程池、连接池、队列或资源配额限制故障影响范围。背压让上游感知下游处理能力并减慢或拒绝流量。熔断不能替代超时、容量保护和重试治理；恢复时应逐渐放量，避免瞬间冲击刚恢复的服务。

### 25. 分布式锁

分布式锁用于协调多个进程对共享资源的临界访问。获取必须原子，锁需有租期以便持有者崩溃后释放；续期存在暂停、网络延迟和租约失效竞态。释放时应校验持有者令牌，不能仅按锁名删除。

租约过期后旧持有者可能恢复并继续写，因此只靠互斥锁不一定保护资源。递增 fencing token 可让资源端拒绝旧令牌写入。锁服务自身的可用性、时钟假设和网络分区都影响安全性。若业务可用唯一约束、乐观版本检查、单写者分区或原子状态转移解决，通常更简单可靠。

### 26. 共识、选主与租约

共识使多个节点在故障条件下对值或日志顺序达成一致，通常依赖多数派。Raft 将工作分为选主和日志复制：领导者把条目复制到多数节点后提交，节点通过任期和日志匹配规则避免旧领导者覆盖已提交数据。多数派不可达时，系统可能停止写入以避免分叉。

租约是在有限时间内授予领导权或资源所有权，依赖时钟偏差和暂停时间假设；租约到期的旧持有者可能仍运行，因此资源侧 fencing 很重要。共识服务适合少量关键元数据和协调，不适合作为所有业务请求的默认路径。要理解故障恢复、脑裂、防止旧主写入以及多数派丢失时的行为。

### 27. 可观测性与 SLO

可观测性帮助从外部信号推断系统内部状态。指标适合趋势和告警；日志记录具体事件及上下文；分布式追踪关联一次请求经过的服务。RED 常看请求率、错误率和时长；USE 常看资源利用率、饱和度和错误。标签应控制基数，日志和追踪需避免敏感信息。

SLI 是衡量服务结果的指标，SLO 是目标区间，错误预算表示允许的不达标额度。告警应提示用户影响或即将耗尽的预算，并能触发行动。平均延迟不能代表尾延迟；单纯 CPU 高也未必等于用户受损。需为关键用户旅程定义成功、失败和统计窗口，并通过演练验证告警能发现问题。

### 28. 认证与授权

认证回答“你是谁”，授权回答“你能做什么”。Session 通常由服务端保存会话状态；Bearer Token 由客户端携带，便于服务间传递但泄露后可被重放。JWT 可在本地验证签名和声明，撤销、密钥轮换和权限及时变化需要额外机制；不要把敏感信息放入可解码的令牌。

OAuth2 授权码流程用于委托授权，身份认证通常结合 OpenID Connect。RBAC 按角色授予权限，管理简单但角色可能膨胀；ABAC 按主体、资源和环境属性决策，灵活但策略更复杂。多租户系统需在每次访问路径执行租户边界校验，并测试横向越权。密钥要安全存储、轮换和审计；最小权限、短期凭据和可追溯操作是基础。
