# 系统设计答题模板

这是一份思考提纲，不是固定答案。围绕题目主要矛盾展开；每个决定都应能关联到需求或约束。

## 1. 需求与范围

- 谁在什么场景下使用系统？核心成功路径是什么？
- 哪些是明确需求，哪些尚不清楚？哪些问题会改变设计？
- 哪些能力暂不覆盖？质量目标之间的优先级是什么？
- 为什么先澄清这些问题？因为同一业务名词可能对应不同状态、责任和成功定义。

## 2. 规模与服务目标

- 估算平均/峰值吞吐、并发、数据增长、保留量和带宽。
- 给出输入、单位、峰值持续时间和估算误差范围。
- 延迟、可用性、正确性、恢复时间和成本分别如何度量？
- 为什么量化？容量和质量目标决定设计边界，避免无依据的复杂化。

## 3. 核心用例、接口与数据

- 列出关键读写操作、调用方、输入输出及失败语义。
- 哪些实体及状态变化是核心？谁有权改变状态？
- 数据如何查询、更新、保留、删除和审计？并发修改如何处理？
- 为什么明确数据和接口？它们界定系统责任，并揭示一致性、幂等和兼容问题。

## 4. 架构边界与主流程

- 画出参与者、信任边界、内部责任及外部依赖。
- 沿关键成功路径逐步说明请求、数据写入、确认和用户可见结果。
- 哪些操作同步完成，哪些可延后？谁是数据权威？
- 为什么从流程推导结构？确保每个组件都承担明确业务责任，且链路可以走通。

## 5. 并发、一致性与失败

- 重复、乱序、并发更新和部分成功会产生什么结果？
- 超时、重试、节点退出、网络分区、依赖不可用和积压时如何处理？
- 如何检测故障、恢复处理、避免重复副作用，并让用户理解当前状态？
- 为什么逐项推演？正常路径成立不代表数据正确或故障后可恢复。

## 6. 安全、运行与演进

- 身份、授权、租户隔离、敏感数据和审计边界是什么？
- 需要哪些指标、日志、追踪、告警、容量保护和恢复演练？
- 如何分阶段上线、迁移、回滚？如何证明验收指标达成？
- 为什么考虑运行周期？设计需要能被验证、维护并安全演进。

## 7. 取舍与结论

- 说明关键选择、备选方案、收益、代价和成立条件。
- 列出最重要的风险、尚未验证的假设及验证方法。
- 若约束变化，指出哪些部分需要重新评估。
- 为什么解释取舍？系统设计是满足约束的选择过程，不是组件清单。
