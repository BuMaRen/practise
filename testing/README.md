# 质量工程练习

从总站进入“质量工程”，按主线和备线练习：

1. **评测证据**：逐步建立 30–50 个真实需求／用例样本，先记给 AI 的生成范围和 P0/P1 取舍，再记验收标准、AI 产物、人工判定、首次运行和失败根因。范围内应做而没做才记为漏测；明确延后的低优先级场景单独跟踪，不计入本轮漏测。每次规则或提示词迭代在同一批样本上记录前后分子、分母、典型失败和证据位置。页面只计算输入的真实数值；AI 可审查证据是否足够支持结论。
2. **Python 自动化**：在接口测试、Playwright、pytest、CI、问题定位和 flaky 治理方向由本地 Claude／Codex CLI 出题；亲手写实现、运行自测，再请 AI 静态评估。AI 不运行代码。
3. **项目案例**：准备两段“问题 → 判断 → 规则调整 → 验证”的案例，并分别写明亲手代码与 AI 协助。AI 会指出证据缺口和可能的面试追问。

页面用“★ 工作中重点积累”标记必须从真实工作取得的样本、基线、代码与运行记录。真实项目事实以代码、日志和评审记录为准；页面练习和 AI 反馈不能充当工作成果。数据在 `data/progress.json`，输入停止后自动保存。

可接着到[系统设计](../system-design/)练 CaseHub／auto-test 的分工、恢复、幂等、追溯、经验复用和自动放行边界；到[算法编码](../coding/)按六类题保持基础编码手感。默认模型与 CLI 配置见根目录 [README](../README.md)。
